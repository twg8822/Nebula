# CLAUDE.md

Notes for Claude Code about this project. Claude reads this file at the start of every session.

## Project overview
**NEBULA**: a browser-based generative galaxy simulator. It draws tens of thousands of stars in logarithmic spiral arms with differential rotation, additive HDR glow, a bright core, and a twinkling background, plus a glass control panel with Randomize. A Preset dropdown loads JSON presets from `presets/`. Toggleable extras: a supermassive black hole (accretion disk + lensing, with optional tidal disruption flares and, in collision mode, gravity), galaxy collision mode (CPU N-body), and a cinematic auto-orbit camera. Planned additions: shareable links and bloom.

## Tech stack
- Vanilla JavaScript ES modules, WebGL2, plain HTML/CSS.
- **No frameworks, no build step, no npm dependencies.** Keep it that way.

## Common commands
- Run: `python3 -m http.server 8000`, then open http://localhost:8000. ES modules don't load over `file://`.
- Stress test: `http://localhost:8000/?starCount=200000` (the max). Any key from `js/config.js` works as a query param, including the 0/1 switches: `?blackHole=1&bhFlares=1&collision=1&bhGravity=1`.
- In the browser console: `nebula.config.<key> = …; nebula.regenerate()`
- Keys: `Space` pauses, `R` randomizes, `H` hides or shows all UI, `F` toggles the FPS HUD, `C` toggles the cinematic camera. Mouse: drag to orbit (with inertia), wheel to zoom, double-click to glide back to the default view.
- Console: `nebula.sim` is the live `CollisionSim` while collision mode is on (e.g. `for (let i=0;i<600;i++) nebula.sim.step(0.05, nebula.config)` to skip ahead). `nebula.flares.trigger(phi)` fires a flare; with Space-paused, set `nebula.flares.age` to freeze one for a screenshot.
- Test: `node --test tests/*.test.js` (or `npm test`). Node 22 (installed 2026-11-19) treats a bare `tests/` argument as a file and fails, so always pass the glob. The tests use Node's built-in runner and have zero dependencies. `package.json` exists only to set `"type": "module"` so Node can load the ES modules; keep it dependency-free. With it, `node --check js/...` and headless imports (e.g. of `CollisionSim`) work directly in the repo. No lint.

## Project structure
- `README.md`: the public description on GitHub (features, controls, how it works, roadmap). Update its Features and Roadmap sections when a phase ships.
- `docs/preview.gif`: the animated preview at the top of the README, with the HUD and panel visible on purpose. It predates the 2026-11-18 defaults and features, so it's due for a re-record. To re-record it: Ubuntu's screen recorder gives a `.webm`, and ffmpeg isn't installed, so extract frames with `gst-launch-1.0` (720 px wide, 12 fps) and assemble the GIF with Pillow using one shared palette. Keep it under ~10 MB (about 10 s), and keep the raw `.webm` out of git.
- `index.html`, `css/style.css`: full-screen canvas and HUD.
- `js/main.js`: bootstrap, resize/DPR, render loop, pass order (see Notes), collision stepping, and the flare timer. Exposes `window.nebula` (config, regenerate, randomize, camera, flares, sim).
- `js/config.js`: every tunable parameter, with min/max/step, `label`, `kind` (`regen` = rebuild buffers, `uniform` = live), and an optional `random` range that `randomize()` draws from. To make a param randomizable, give it a `random` range here.
- `js/ui/panel.js`: glass control panel. Its `CONTROLS` list picks which params to show and how to format them; ranges and labels come from `config.js`. `regen` changes trigger a debounced regenerate in `main.js`. Row options: `toggle` (0/1 param as a switch), `showIf` (only visible while that toggle is on; works on toggles too), `hint` (small dim note after a toggle's label), `divider`, `commitOnRelease`, `invert`. Feature toggles are 0/1 numbers in `config.js` with no `random` range, so Randomize never flips them and `?blackHole=1` works as a URL param.
- `presets/`: one JSON file per preset (kebab-case name, every `config.js` key, numbers only) plus `index.json` (array sorted by file name, which the dropdown reads; an entry may be `{"file", "name"}` to give a display name a file name can't spell, e.g. "Devourer's Waltz"). `lavender-whirlpool.json` is the original Neon Whirlpool, kept when Neon Whirlpool was retuned darker on 2026-11-19. `presets/default.json` mirrors the user's defaults. Validate with `python3 .claude/skills/preset/validate.py --all`.
- `js/ui/presets.js`: `loadPresets()` reads `presets/index.json`, falling back to the http.server directory listing. `applyPreset()` in `config.js` resets every key to its default, then applies the preset with `sanitize()`. The panel's "Preset" select goes back to "Custom" after any manual change, Randomize or `C`; when presets load it selects whichever preset matches the current config (so a clean load shows "Default").
- `.claude/skills/preset/`: the `/preset <description>` skill (SKILL.md, with a vibe→knob guide and a JSON schema generated from config.js) and `validate.py`, which checks presets against the live `config.js`.
- **When you add, remove or re-range a param in `config.js`**: update `presets/default.json` if the default changed, then run the validator. Missing keys fail validation (the app itself falls back to defaults for them). Regenerate the schema in `SKILL.md` too.
- Anything with class `.ui` is hidden by `H` (via `body.ui-hidden`).
- `src/math.js`: all pure math (seeded RNG, rotation curve, `orbitAngle`, `spiralArm`, `diskPosition`, `temperatureTint`, `colorFilter`). The app uses it through `js/math/random.js` and `js/galaxy/rotation.js` (re-exports), `generator.js`, `collision.js` and `compositor.js`. The GLSL can't import it, so `temperatureTint` and the star orbit formula exist twice; `tests/math.test.js` checks that the shader constants still match. **Refactors here must not change output**: the 2026-11-18 extraction was verified with byte-identical fingerprints of every preset's buffers, the background, and collision sims.
- `.claude/settings.json` + `.claude/hooks/test-src.sh`: a PostToolUse hook on Edit|Write. Any edit to a file in `src/` runs `node --test tests/*.test.js`. Passing is silent; failing blocks and feeds the failing tests back, so fix them before anything else. Review or disable it in `/hooks`.
- `tests/math.test.js`: unit tests for `src/math.js` (golden RNG values, rotation curve, log-spiral pitch, luminance-preserving tints, filter neutral at 0, shader sync).
- `js/galaxy/generator.js`: builds per-particle orbital elements (r, θ0, height, size, rgb, brightness, lock) for stars (arm, bulge, field and halo populations), haze and dust.
- `js/galaxy/rotation.js`: rotation curve Ω(r) = v0/√(r²+rc²). **It must match** `js/shaders/stars.js`.
- `js/galaxy/collision.js`: `CollisionSim`. Restricted N-body for collision mode (see Notes).
- `js/render/blackHole.js`: `AccretionDisk` mesh and `FlareTimer`; the lensing itself is the `LENSING` variant of `js/shaders/composite.js`, compiled as a second program in `Compositor`.
- `js/shaders/*.js`: GLSL as exported template strings, so nothing needs fetching.
- `js/render/`: `StarLayer`, `BackgroundLayer`, `CoreGlow` and `Compositor` (tone map).
- `js/gl/`: context, program compile/link helpers, and the HDR (RGBA16F) framebuffer.
- `js/camera/camera.js`: orbit camera. The disk lies in the XZ plane, with Y up. Input writes `camera.goal`; shown values ease toward it with dt. Cinematic offsets (tilt sway, zoom breathing) are scaled by a 0..1 blend and get baked into the goal when the user takes over, so nothing jumps. `camera.targetGoal` is where it looks (the collision focus, else the origin). It runs on real time, so it keeps moving while paused. Framing (`fitCamera` / `panelShift` in `main.js`): distance = 2.6 × `galaxyRadius` (26 at the default 10), or at least 4.8 × in collision mode, refitted only when the radius or mode changes so a manual zoom survives; `camera.shift` is an off-axis projection shift (NDC, eased) that centres the galaxy in the space left of the open panel, 0 when the panel is collapsed, hidden (`H`) or covers over half the window.

## Notes & decisions
- In normal mode, motion is analytic on the GPU: θ = θ0 + ω·t, where ω = mix(Ω(r), Ωp, lock). The CPU only uploads `uTime`.
- **Winding problem:** pure differential rotation winds the inner arms into concentric rings within minutes. Arm tracers (young stars, knots, dust, arm haze) therefore have `lock = 1` and ride the spiral pattern speed Ωp, which is Ω at `corotation × galaxyRadius`. Old arm stars use 0.8; bulge, field and halo use 0. Setting `armLock = 0` restores free winding.
- Collision mode switches to restricted N-body on the CPU. All stars, haze and dust (both galaxies) are test particles in two moving potentials: the host is a log halo Φ=½v0²ln(d²+rc²), which reproduces the analytic rotation curve exactly so the disk is in equilibrium, and the companion is a Plummer sphere with M = q·v0²·R. The cores attract each other, with mild dynamical friction near the host. Leapfrog KDK, substeps ≤0.05. Cost: about 2.5 ms/frame at 79k particles (50k stars), about 4.7 ms at 174k (the 110k default). The core orbit is set at pericenter and integrated backward `LEAD_TIME` (40 sim units), and sim time advances at dt·collisionRate only (deliberately independent of `timeScale`; the user wants the two speeds separate), so at the default 1.0 the first pass comes about 40 s after the switch; the orbit is bound and friction slowly merges the pair. Tuned defaults (companion mass 0.35, pericenter 1.0R, pericenter speed 1.4·v0) strip about 10% of host stars and 14% of companion stars into tails; the first try (0.25, 1.2R, 1.6·v0) gave weak tails. Host particles start at their current analytic angle, so the switch is seamless. `StarLayer` then uses `STAR_VS_POS` (positions from a DYNAMIC buffer at attrib 3). Arm-locked tracers wind freely in this mode; that's expected.
- Black hole extras (both 0/1 switches nested under Black hole, off by default; with them off the code paths are skipped):
  - `bhFlares`: a tidal disruption flare drawn in the accretion disk shader (head spirals inward trailing a thin stream, and the disk brightens; 3.5 s). The user asked twice for it to be subtler and approved the current values (stream gain 1.4, width `span·(0.007 + 0.004·behind)`, disk boost 0.35); don't make it more prominent without asking. `FlareTimer` in `js/render/blackHole.js` fires one every 10–25 s at random, or when the collision sim reports a capture, with a 4 s cooldown. It runs on unpaused real time. Console: `nebula.flares.trigger(phi)`.
  - `bhGravity`: collision mode only (normal mode is deliberately unchanged; at a realistic mass it would be sub-pixel). Adds a Plummer black hole at the host core, M = 0.08·v0²·R·bhMass (exaggerated about 100×), softening 0.15, capture radius 0.3·bhMass. Host particles start outside 2× the capture radius, with circular speeds that include the black hole, so the core stays stable; captures only happen once the encounter knocks stars onto plunging orbits. Captured particles are parked at 1e6 (beyond the far plane). Mass follows the size slider live. Toggling it, or toggling Black hole while it's on, restarts the collision. Typical run (in sim units; at the default collisionRate 1.0, 1 unit = 1 s): no captures until the cores close in (first ones at about 120 units), a feeding peak during the merger (about 180), about 10% of particles swallowed in total, then quiet by about 350. Cost: about +1.2 ms/step at 174k particles.
- Black hole lensing is screen-space in the tone-map pass, so it bends everything near the hole, including foreground stars. Its size is artistic: θE = `bhMass` in world units, the horizon is 0.5θE and the disk spans 1.2–3.5θE. With it off, the original composite program runs unchanged, so the default look is pixel-identical.
- **Defaults are the user's choices** (2026-11-18): 110k stars, 4 arms, pitch 18° (shown as 59% tightness), rotation 2.5×, core size 1.95, color temperature −0.37 (cool), glow 0.8; camera viewing angle (pitch) 20° (in `js/camera/camera.js`) with ±12° cinematic sway (`tiltDeg`). Don't change them without asking. When the user says "tilt" they may mean the viewing angle, not the sway.
- Color filter (`tintStrength`, `tintHue`): `colorFilter()` (`src/math.js`) gives a multiplier that is applied to the galaxy's emitting layers (stars, haze, core glows, accretion disk, photon ring) via `uTint`, not in the tone-map pass, so the background sky keeps its natural color (changed 2026-11-19 after the art review). Dust doesn't need it: tinting the light before absorption is mathematically the same. The hue is at 80% saturation, normalized to luminance 1 so brightness holds, and blended in by strength. Strength 0 returns exactly `[1,1,1]`, so the image is unchanged; that no-effect guarantee was a user requirement. The panel hides Filter hue until the filter is above 0. No `random` range.
- Browser caching: `python3 -m http.server` lets Chrome cache modules. Hard-reload (Ctrl+Shift+R) after edits.
- Visual checks use the Playwright MCP (user's preference since 2026-11-19; it runs on the real GPU at 60 fps). Output goes to the git-ignored `.playwright-mcp/`. For repeatable before/after shots: `clock.install` then `clock.pauseAt` before `goto` and step with `clock.runFor` (rAF runs on the fake clock); add `timeScale=0` for pixel-exact comparisons (only twinkle differs); and disable the cache through CDP (`Network.enable` then `Network.setCacheDisabled`), or stale modules load. Pages opened with `newPage()` and no fake clock may not animate at all (background tab). Claude in Chrome is the fallback; its automated window can be throttled to 1 fps.
- Arms are generated *trailing* (θ decreases with r), which matches the direction differential rotation winds them.
- Tone map highlight handling (2026-11-19): when a channel would overflow, the hue-preserving result is scaled back, which used to flatten bright or strongly tinted cores into one uniform disc. The per-channel ACES blend now rises from 0.3 to 0.85 as the overflow goes from 1× to `BLEACH_FULL` (2.5×) in `js/shaders/composite.js`, giving a white-hot centre and coloured rim. Pixels that don't overflow use the original 0.3 exactly, so the default galaxy's core is unchanged to within 1–2 levels.
- Haze edge fade (`EDGE` in `js/shaders/stars.js`, haze only via `uEdgeFade` = galaxy radius): sprites shrink and dim past a fraction of the radius so sparse gas doesn't read as separate cotton balls. Gentle in the analytic disk (0.75–1.15 R, to 80% size and 60% light) to keep the user's soft, puffy arms; strong in collision mode (0.6–1.1 R from the nearer core, to 55% size and 30% light) so tails read as faint star streams.
- Photon ring: a thin Gaussian ring at 1.05 × the shadow radius in the `LENSING` composite (`uRing` = `PHOTON_RING` × accretion glow × tint, set in `main.js`).
- Draw order into the HDR buffer: background → haze → stars → core glow(s) → accretion disk (all additive) → dust (absorbing: `blendFunc(ZERO, ONE_MINUS_SRC_COLOR)`). Then a hue-preserving ACES tone map keeps the core yellow-orange instead of clipping to white. Lensing lives in `Compositor`; bloom will too (put it after lensing).
- Stars, haze and dust all use the same orbital-element layout and vertex shader (`StarLayer` with a different fragment shader and blend mode), so dust lanes and glow stay locked to the arms as they wind.
